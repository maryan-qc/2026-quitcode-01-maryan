# Хрестики-нулики

Гра в хрестики-нулики на **Next.js 16 (App Router)** та
**[Porsche Design System](https://designsystem.porsche.com/) v4**.

**Живе демо:** https://maryan-qc.github.io/2026-quitcode-01-maryan/

## Запуск

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # продакшн-збірка
```

Потрібен Node 22+.

## Що вміє

Два режими на вибір із головного меню.

**Локально** — двоє грають на одному пристрої.

**Онлайн** — один створює кімнату й отримує код із 5 символів, другий вводить
його (або відкриває посилання-запрошення) і вони грають з різних пристроїв:

- код можна скопіювати кнопкою або передати посиланням `?room=XXXXX`;
- видно, чий зараз хід, за кого ви граєте і чи суперник ще на зв'язку;
- ходити поза своєю чергою не можна — хід відхиляється;
- реванш без перепідключення, рахунок зберігається.

Спільне для обох режимів:

- визначення переможця з підсвіткою виграшної лінії, визначення нічиї;
- рахунок X / нічиї / O між раундами;
- наступний раунд починає той, хто програв попередній;
- світла й темна теми — автоматично за системними налаштуваннями.

## Структура

| Шлях | Призначення |
|---|---|
| `lib/game.ts` | чиста логіка гри: виграшні лінії, результат, хід, наступний раунд |
| `lib/room.ts` | коди кімнат, посилання-запрошення, протокол повідомлень |
| `app/tic-tac-toe.tsx` | екрани: меню, локальна гра, лобі, очікування, онлайн-дошка |
| `app/use-online-game.ts` | P2P-з'єднання, синхронізація стану, реванш, розриви |
| `app/use-room-invite.ts` | читання `?room=` без hydration mismatch |
| `app/board.tsx`, `app/scoreboard.tsx` | презентаційні компоненти |
| `app/tic-tac-toe.module.css` | розкладка й клітинки поля на дизайн-токенах PDS |
| `app/layout.tsx` | `PorscheDesignSystemProvider` + `.scheme-light-dark` |
| `app/globals.css` | глобальні стилі PDS (змінні, шрифти, normalize) |

## Як влаштована онлайн-гра

GitHub Pages роздає лише статику — сервера немає. Тому браузери з'єднуються
**напряму через WebRTC** ([PeerJS](https://peerjs.com/)), а публічний брокер
PeerJS потрібен лише щоб вони знайшли одне одного за кодом кімнати. Після
рукостискання дані йдуть повз нього.

Код кімнати перетворюється на peer id `quitcode-ttt-<код>` — саме за ним гість
набирає хоста. Алфавіт коду без схожих символів (без `0`/`O`, `1`/`I`/`L`), щоб
його можна було продиктувати голосом.

**Хост — джерело істини.** Він тримає стан гри, перевіряє кожен хід (чи черга
того, хто ходить; чи клітинка вільна) і розсилає новий стан. Гість надсилає лише
наміри (`move`, `rematch`), тому розсинхрону між дошками бути не може.

Обмеження публічного брокера: він best-effort, а TURN-сервера в нього немає —
за строгим корпоративним NAT або файрволом з'єднання може не встановитись.
Для гарантованої роботи в будь-якій мережі потрібен власний бекенд
(наприклад Firebase Realtime Database або Cloudflare Durable Object).

## Нотатки про Porsche Design System у Next.js

- Усі компоненти імпортуються з підпакету `@porsche-design-system/components-react/ssr` —
  він рендерить розмітку як Declarative Shadow DOM на сервері.
- Глобальний CSS підключається за явним шляхом
  `@import "@porsche-design-system/components-react/index.css"`. Скорочений
  варіант без `/index.css` Turbopack мовчки ігнорує — стилі просто не потрапляють
  у бандл.
- `next.config.ts` вимикає поліфіл `light-dark()` у Lightning CSS
  (`lightningCssFeatures.exclude`), бо на ньому ламається палітра PDS.
- Теми перемикаються лише класом `.scheme-*` — пропа `theme` в PDS v4 немає.

## Деплой на GitHub Pages

```bash
npm run build:pages
```

Збирає статику в `app/out/` з `basePath=/2026-quitcode-01-maryan` (вмикається
змінною `GITHUB_PAGES=true`, локальні `dev`/`build` лишаються на корені) і додає
`.nojekyll`, щоб Pages не ігнорував теку `_next`. Вміст `out/` публікується
в гілку `gh-pages`, з якої й роздається сайт.
