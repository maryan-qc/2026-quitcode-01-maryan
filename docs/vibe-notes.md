## 1. Що вийшло з першого промпту, а що ні

**Вийшло одразу:**

1. **Каркас проєкту.** `create-next-app` з явними прапорцями (`--typescript --app
   --no-tailwind --eslint --no-src-dir --yes`) відпрацював без жодного питання —
   жодної інтерактивної підказки, які зазвичай блокують агента.
2. **Уся логіка гри з першої спроби.** [`lib/game.ts`](../app/lib/game.ts) —
   виграшні лінії, `getResult`, визначення нічиї — не редагувалась жодного разу
   після написання. Так само компонент [`tic-tac-toe.tsx`](../app/app/tic-tac-toe.tsx):
   `tsc --noEmit`, `next build` і `eslint` пройшли з першого запуску, нуль помилок.
3. **Типізація PDS.** Замість того щоб вгадувати пропси, я попросив агента
   вичитати `.d.ts` з `node_modules`. Усі значення (`variant="success"`,
   `color="contrast-low"`, іконки `flag`/`refresh`/`delete`) звірені з union-типами
   до збірки — тому й нуль TS-помилок.

**Не вийшло з першого разу:**

4. **Глобальні стилі PDS мовчки не підключились.** Офіційний гайд PDS для Next.js
   показує скорочений `@import '@porsche-design-system/components-react'`.
   Turbopack його **проігнорував без жодної помилки чи попередження** — збірка
   зелена, сторінка рендериться, але CSS-бандл вийшов **257 байт** замість
   16 КБ: жодного `--p-color-*`, жодного `@font-face`. Виправляє лише явний шлях
   `/index.css`.
5. **Node не той.** Системний Node — v20.10.0, репо просить 22+. Довелось
   перемикатись на v24 через nvm у кожній команді (`. "$NVM_DIR/nvm.sh" && nvm use 24`),
   бо змінні оболонки між викликами не зберігаються.

## 2. Де агент спіткнувся і як я його розвернув

### Пастка №1 — «зелена збірка» ≠ робочий UI

Найцікавіший момент сесії. Після `npm run build` без помилок спокуса —
поставити галочку і йти далі. Замість цього агент підняв dev-сервер і
**перевірив, що саме потрапило в бандл**:

```bash
curl -s http://localhost:3000/_next/static/chunks/<hash>.css | wc -c   # → 257
```

257 байт — це лише мій власний CSS. Стилів дизайн-системи там не було взагалі.
Ні збірка, ні лінтер, ні TypeScript про це не сказали б ніколи.

Промпт, який розвернув: **«перевір, що PDS реально рендериться, а не просто
збирається»**. Після заміни на `/index.css` — 16 389 байт, 33 колірні токени,
21 `@font-face`, усі класи `.scheme-*`.

### Пастка №2 — верифікація очима, а не «має працювати»

Далі агент не просто зробив скриншот, а **зіграв партію** через Chrome DevTools
Protocol: клік по клітинках 0→3→1→4→2, і перевірка стану DOM після кожного ходу.

```
AFTER X WINS: {"cells":["X","X","X","O","O","","","",""], "disabled":true,
               "winningHighlighted":[0,1,2], "tag":"Переміг X"}
AFTER NEW ROUND: {"cells":["","","","","","","","",""], "tag":"Ходить O"}
```

Це підтвердило не лише перемогу, а й дрібну логіку, яку легко зламати непомітно:
наступний раунд починає той, хто програв (тому `Ходить O`).

### Пастка №3 — знання моделі про PDS були б застарілі

Ключова знахідка: пакет `@porsche-design-system/components-react` **містить
власний Claude-скіл** — `node_modules/@porsche-design-system/components-react/skills/pds-knowledge-react/`.
Це документація, згенерована рівно під встановлену версію 4.6.0.

Саме звідти прийшли два факти, які модель інакше взяла б із застарілого
тренувального знання:

- пропа `theme` у PDS v4 **не існує** (була в v3) — теми лише через клас `.scheme-*`;
- для Next.js імпортувати треба з підпакету `/ssr`, який рендерить
  Declarative Shadow DOM на сервері.

Мораль: перед тим як писати код під незнайому бібліотеку — подивитись, чи не
лежить документація прямо в `node_modules`.

Розрахунок за прайсом Claude Opus 5: input $5 / 1M, output $25 / 1M,
запис у кеш ×1.25 ($6.25 / 1M), читання з кешу ×0.1 ($0.50 / 1M).

**Що видно з цифр:** 96.8% усіх токенів — це **читання з кешу**, і коштує воно
$5.06 із $10.11. Тобто половина рахунку — просто за те, що контекст сесії
перечитується на кожному з 135 запитів. Другий за вагою рядок — output ($1.72
за 82 тис. токенів). Власне «новий» input — 270 токенів, тобто $0.001, шум.

Розмір результату для порівняння: **420 рядків** власного коду (`lib/game.ts` 37,
`tic-tac-toe.tsx` 173, `tic-tac-toe.module.css` 120, решта — конфіги й layout).

## 4. Спостереження — що зробив би інакше

1. **«Збірка пройшла» — це не перевірка.** Найсерйозніший баг сесії (порожній
   CSS дизайн-системи) був абсолютно невидимий для `tsc`, `eslint` і
   `next build`. Знайшовся тільки тому, що агент витягнув реальний бандл
   і порахував байти. Наступного разу критерій приймання формулюю одразу як
   «покажи, що працює в браузері», а не «зроби, щоб збиралось».

2. **Спершу `node_modules`, потім інтернет.** Скіл `pds-knowledge-react`
   усередині пакета виявився точнішим за будь-який гайд, бо згенерований під
   версію 4.6.0. Гайд зі сторінки документації, до речі, і містив той самий
   помилковий скорочений `@import`. Наступного разу перше питання агенту —
   «що корисного вже лежить у пакеті?».

3. **Дешеві верифікації варто просити явно.** Прогін партії через CDP зайняв
   один інструментальний виклик, а перевірив разом: логіку перемоги, підсвітку
   лінії, блокування поля, рахунок і чергу ходів. Значно дешевше, ніж три
   ітерації «здається, працює» → «ні, не працює».

4. **Кеш — головна стаття витрат, і на неї можна впливати.** 96.8% токенів
   пішло на перечитування контексту. Розбити роботу на дві коротші сесії
   (каркас + DS окремо, гра окремо) вийшло б помітно дешевше за одну довгу.
