# A/B промптів (Task 4)

**Підзадача:** додати в меню гри поле «Ім'я гравця» з валідацією; ім'я має
зберігатися разом з рекордом і показуватись колонкою в таблиці рекордів.

**Умови експерименту.** Обидва промпти виконувались у **чистому контексті**:
дві однакові копії теки `app/` (перевірено `diff -rq`), два окремі
неінтерактивні запуски Claude Code, однаковий набір дозволених інструментів,
однакова модель (Opus 5). Цифри не з ока, а з `--output-format json`:

```bash
claude -p "$(cat prompt-x.txt)" --output-format json \
  --permission-mode acceptEdits \
  --allowedTools "Read Edit Write Glob Grep Bash(npm run build)" \
  --strict-mcp-config --max-budget-usd 4
```

## Промпт A — базовий

```
Додай у гру форму введення імені гравця з валідацією.
```

## Промпт B — структурований

```
РОЛЬ
Фронтенд-інженер, який працює з Porsche Design System v4.6.0 у React 19 + Vite + TypeScript.

КОНТЕКСТ
У цій теці — гра «Змійка». Меню зібране в src/components/SettingsPanel.tsx, таблиця
рекордів — у src/components/Scoreboard.tsx, робота зі сховищем — у src/game/scores.ts
і src/game/settings.ts. Тип Score уже має поля score, apples, speed, boardSize,
passThroughWalls, playedAt.

ЗАВДАННЯ
Додати поле «Ім'я гравця» в меню перед стартом партії. Ім'я має зберігатися разом
з рекордом і показуватись окремою колонкою в таблиці рекордів.

ОБМЕЖЕННЯ
- UI будувати лише з компонентів PDS, без власного CSS для елементів форми.
- API компонентів звіряти з node_modules/@porsche-design-system/components-react/skills/pds-knowledge-react,
  а не з пам'яті: у v4 частина пропів змінилась (пропа theme більше немає).
- Ім'я зберігати в localStorage разом з рештою налаштувань, з тими самими
  запобіжниками проти битого JSON, що вже є в settings.ts.
- Старі записи рекордів без імені мають лишатись читабельними, а не ламати таблицю.
- Не змінювати ігрову логіку в src/game/engine.ts.

КРИТЕРІЇ ПРИЙМАННЯ
1. `npm run build` проходить без помилок.
2. Порожнє ім'я або довше за 20 символів показує стан error і повідомлення
   українською, і партія з таким ім'ям не стартує.
3. Ім'я з'являється в таблиці рекордів для нових партій, а старі рядки без імені
   показують прочерк.

ФОРМАТ ВІДПОВІДІ
Спочатку список змінених файлів, по одному в рядку. Потім — короткий опис рішення.
Наприкінці — одне речення про те, що саме ти перевірив і як.
```

## Висновок

**За 7% вартості структурований промпт закрив на один критерій приймання
більше і не залишив UX-огріху.** Різниця в ціні мізерна — майже весь бюджет обох
прогонів з'їло читання з кешу (96% токенів), тобто сам код проєкту, а не текст
промпту. Довший промпт коштує майже нічого: 300 зайвих слів — це сотні токенів
на фоні мільйона.

Найцінніше дала не «роль» і не «контекст», а **критерії приймання**. Саме вони
перетворили розмите «з валідацією» на дві конкретні перевірки — і саме другу з
них (ліміт довжини) базовий прогін не зробив узагалі. Пункт про формат відповіді
теж окупився: список змінених файлів одразу видно, не треба вичитувати переказ.

**Але критерії треба писати, знаючи UI.** Обидва прогони поставили на поле
`maxLength={20}`, тож увести 21 символ у браузері неможливо — і гілка з
повідомленням «не довше за 20», яку я вимагав критерієм, майже недосяжна.
Тобто критерій приймання, сформульований без огляду на те, чи взагалі можна
дійти до такого стану, дає код, який формально є, а фактично не працює ніколи.
Наступного разу критерій звучав би як «ліміт довжини не дає ввести більше 20
символів» — і перевірявся б у браузері, а не в коді.
