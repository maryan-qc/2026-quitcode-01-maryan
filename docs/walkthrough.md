# Домашнє завдання — Воркшоп 1

**Тема:** Сучасний стан агентної інженерії. Від no-code до AI-розробки
**Формат:** greenfield — ви створюєте власний невеликий проєкт-автоматизацію
**Час:** ~1–2 години
**Здача:** Pull Request у starter-repo (CodeRabbit зробить авто-рев'ю)

---

## Task 1: Init проєкту + конфіг агента _(~25 хв)_

**Мета:** запустити новий проєкт і налаштувати під нього агентне середовище.

1. Ініціалізуйте невеликий **TypeScript-проєкт** у теці `app/` (рекомендовано —
   vanilla TS без фреймворків):
   ```bash
   mkdir app && cd app
   npm init -y
   npm i -D typescript tsx vitest @types/node
   npx tsc --init
   ```
   (можна інший стек — головне, щоб були команди запуску й тестів).
2. Додайте `app/AGENTS.md` із:
   - стеком і версіями;
   - командами (`dev`/`start` / `test`);
   - 3–5 конвенціями (нейминг, структура, стиль);
   - 2–3 guardrails (що НЕ чіпати, чого не робити — напр. «жодних секретів у
     коді, конфіги лише з env»).
3. Обмежте контекст агента — мінімум **3 патерни**, що прибирають з контексту
   `node_modules`, білди, lock-файли, `.env`:
   - Cursor: `.cursorignore`;
   - Claude Code: `.claude/settings.json` з `permissions.deny` (напр.
     `Read(./.env*)`).
4. Встановіть мінімум один готовий **Agent Skill** під ваш стек:
   ```bash
   npx skills add vercel-labs/agent-skills --skill typescript-best-practices
   ```
   (каталог скілів — [skills.sh](https://www.skills.sh/); підійде будь-який
   доречний скіл). Скіл потрапить у `.agents/skills/` (або теку вашого
   інструмента) — закомітьте його.
5. Перший запит до агента: «прочитай AGENTS.md і опиши проєкт». Переконайтеся,
   що контекст «зчитався».

> Skills — окрема велика тема (Воркшоп 4). Тут достатньо встановити готовий і
> переконатися, що агент його бачить.

**Перевірка:** є `app/` (працює `npm test`), `app/AGENTS.md`, `.cursorignore`
(або deny-правила), встановлений скіл.

---

## Task 2: Міграція міні-воркфлоу через режими _(~35 хв)_

**Мета:** відтворити логіку реального n8n-воркфлоу в коді, керуючи агентом
через режими — це перша ітерація наскрізного треку курсу.

1. Вивчіть матеріали: [`materials/workflow-description.md`](../materials/workflow-description.md)
   і [`materials/n8n-lead-intake.workflow.json`](../materials/n8n-lead-intake.workflow.json).
2. Сформулюйте **acceptance criteria** (4–6 пунктів) **до** написання коду —
   бізнес-правила з опису воркфлоу вам у поміч.
3. Пройдіть задачу у двох режимах:
   - **Plan** — дайте агенту опис + JSON-експорт, попросіть план міграції
     (файли, кроки, тести), відрев'юйте і скоригуйте;
   - **Agent** — виконайте за погодженим планом.
4. Результат у `app/`:
   - модуль(і) з логікою: валідація → нормалізація → сегментація → дії
     (нотифікація-заглушка + запис у CSV/JSON-реєстр);
   - **мінімум 3 тести** (vitest): валідація, нормалізація бюджету, hot/cold;
   - `npm test` зелений.
5. Опишіть процес у `docs/workflow.md`:
   - acceptance criteria;
   - що робили в кожному режимі;
   - що скоригували після рев'ю плану;
   - де агент помилився і як ви це виправили.

**Перевірка:** логіка відповідає опису воркфлоу; тести зелені;
`docs/workflow.md` конкретний, не загальні слова.

---

## Task 3: Аналіз токенів і вартості _(~25 хв)_

**Мета:** ПОМІРЯТИ, а не вгадувати вартість.

1. Зафіксуйте споживання токенів за Task 2 (usage-екран вашого інструмента,
   `/cost` у Claude Code) та/або запустіть `npx repomix` в `app/`, щоб побачити
   розмір контексту в токенах.
2. Прикиньте вартість: `токени × ціна обраної моделі`.
3. Знайдіть **2–3 оптимізації** (вужчий контекст, дешевша модель для рутини,
   коротші сесії, чіткіші промпти).
4. (Опц.) Порівняйте з n8n: скільки коштував би цей флоу на вашому тарифі.
5. Запишіть у `docs/cost-analysis.md`: числа + висновки.

**Перевірка:** `docs/cost-analysis.md` містить реальні числа й ≥2 висновки.

---

## Task 4 (bonus): A/B промптів _(~15 хв)_

**Мета:** відчути різницю базового і структурованого промпту.

1. Візьміть одну підзадачу з Task 2 (напр. «нормалізація бюджету») і напишіть
   **два промпти**:
   - базовий («зроби X»);
   - структурований (роль + контекст + обмеження + acceptance criteria +
     формат відповіді).
2. Виконайте обидва (чистий контекст для кожного), зафіксуйте різницю
   (якість, ітерації, токени).
3. Запишіть у `docs/ab-experiment.md`: обидва промпти + короткий висновок.

> Бонус — не обов'язковий, але це гарний розгін перед Воркшопом 2
> (промпт-інженерія та безпека).

## Definition of Done

- [ ] **Task 1:** `app/` з робочим `npm test` + `app/AGENTS.md` + `.cursorignore`
      (≥3 патерни) або deny-правила + встановлений Agent Skill
- [ ] **Task 2:** логіка Lead Intake у коді відповідає
      `materials/workflow-description.md` + ≥3 зелені тести + `docs/workflow.md`
      (plan → agent + рев'ю)
- [ ] **Task 3:** `docs/cost-analysis.md` з реальними числами + 2–3 висновки
- [ ] **Task 4 (bonus):** `docs/ab-experiment.md` з обома промптами
- [ ] Жодних секретів у git (`.env` — в `.gitignore`)
