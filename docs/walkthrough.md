# Домашнє завдання — Воркшоп 1

**Тема:** Сучасний стан агентної інженерії. Від no-code до AI-розробки
**Формат:** вайб-кодинг — відчути швидкість агентної розробки на власні очі
**Час:** ~1–1.5 години
**Здача:** Pull Request у starter-repo (CodeRabbit зробить рев'ю)

Мета першої домашки проста: **завайбкодити невеликий, але красивий застосунок**
з готовою дизайн-системою — і чесно записати, що вийшло і скільки це коштувало.
Без правил, скілів і тестів — усе це системно додамо у наступних воркшопах.

## Task 1: Каркас + дизайн-система _(~15 хв)_

**Мета:** порожня тека → проєкт з підключеною дизайн-системою.

1. Створіть Vite-проєкт у теці `app/`:
   ```bash
   npm create vite@latest app -- --template react-ts
   cd app && npm install && npm run dev
   ```
   (інший стек теж можна — головне, щоб були команди `dev` і `build`).
2. Підключіть **готову дизайн-систему**. Рекомендуємо
   [Porsche Design System](https://designsystem.porsche.com/) — відкриту,
   «дорослу», з формами й таблицями:
   ```bash
   npm i @porsche-design-system/components-react
   ```
   Далі просто скажіть агенту: «підключи Porsche Design System
   (PorscheDesignSystemProvider) і покажи на сторінці p-heading і p-button».
3. Альтернативи — на ваш смак: інша готова DS (Material UI, Ant Design,
   shadcn/ui) або **власна міні-дизайн-система** (наприклад, згенерована через
   Claude Design). Умова одна: UI будується з компонентів системи, а не з
   голого CSS.

**Перевірка:** `npm run dev` відкривається, на сторінці видно хоча б один
компонент дизайн-системи.

---

## Task 2: Вайб-кодинг застосунку _(~45 хв)_

**Мета:** робочий міні-застосунок, зібраний лише промптами.

**Ідея за замовчуванням — «Lead Desk»** (можна і свою, схожого масштабу:
трекер звичок, калькулятор кошторису, міні-каталог — що завгодно):

- форма заявки: ім'я, email, бюджет, повідомлення;
- список заявок з бейджем **hot / cold** (hot — бюджет ≥ $1000 або «терміново»
  в повідомленні);
- збереження в `localStorage`, кнопка очищення.

**Правила вайбу** (це все одно інженерія, просто швидка):

1. Короткі промпти-ітерації: «додай бейдж», а не «зроби все інакше».
2. Дивіться диф перед прийняттям кожної зміни.
3. `git commit` після кожної вдалої ітерації — це ваші save points; зламалось —
   відкотили й повторили промпт точніше.
4. UI — з компонентів дизайн-системи; агенту так і кажіть.

**Перевірка:** застосунок робить щось осмислене, виглядає «як продукт»,
`npm run build` проходить без помилок.

## Task 3: Нотатки й вартість _(~20 хв)_

**Мета:** зафіксувати досвід і ПОМІРЯТИ вартість, а не вгадувати.

Створіть `docs/vibe-notes.md` і запишіть:

1. **Що вийшло з першого промпту, а що ні** — 3–5 пунктів конкретики.
2. **Де агент спіткнувся** і як ви його розвернули (яким промптом).
3. **Числа:** скільки промптів-ітерацій; токени/вартість сесії (usage-екран
   вашого інструмента, `/cost` у Claude Code; опційно `npx repomix` в `app/`
   для розміру контексту).
4. **2–3 спостереження** — що зробили б інакше наступного разу.

**Перевірка:** у файлі є реальні числа, а не «десь багато токенів».

---

## Task 4 (bonus): A/B промптів _(~15 хв)_

1. Візьміть одну підзадачу з Task 2 (напр. «форма з валідацією email») і
   напишіть **два промпти**: базовий («зроби форму») і структурований
   (роль + контекст + обмеження + критерії + формат).
2. Виконайте обидва (чистий контекст для кожного), зафіксуйте різницю
   (якість, ітерації, токени).
3. Запишіть у `docs/ab-experiment.md`: обидва промпти + короткий висновок.

> Бонус — не обов'язковий, але це гарний розгін перед Воркшопом 2
> (промпт-інженерія та безпека).
