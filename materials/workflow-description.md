# Lead Intake & Routing — опис воркфлоу

Навчальний аналог типового клієнтського флоу агенції: обробка заявок (лідів) з
форми на сайті. Поруч лежить його n8n-експорт:
[`n8n-lead-intake.workflow.json`](./n8n-lead-intake.workflow.json).

## Що робить воркфлоу

```
Webhook (POST /lead-intake)
  → Validate & Normalize (Code)
     → IF Valid?
         ├─ так → Score & Segment (Code)
         │          → IF Hot?
         │              ├─ hot  → Notify Sales (Slack #sales) ┐
         │              │                                      → Append to Leads Sheet → Respond 200
         │              └─ cold ───────────────────────────────┘
         └─ ні  → Respond 400 (список помилок)
```

## Бізнес-правила (це — специфікація для міграції)

1. **Вхід** — JSON-заявка: `name`, `email`, `message` (обов'язкові),
   `budget`, `source` (опційні).
2. **Валідація:** порожні `name` / `email` / `message` → помилка; `email` має
   відповідати простому regex. Невалідна заявка → відповідь `400` зі списком
   помилок (`{ ok: false, errors: [...] }`).
3. **Нормалізація:** trim усіх полів; `email` → lowercase; `source` → lowercase,
   за замовчуванням `"website"`; `budget` — з рядка на кшталт `"$1,500"` чи
   `"1 500 USD"` → ціле число `1500` (немає/сміття → `0`); додається
   `receivedAt` (ISO-час).
4. **Сегментація:** `hot`, якщо `budget >= 1000` **або** `message` містить
   терміновість (`терміново`, `urgent`, `asap`, `якнайшвидше`, без регістру);
   інакше `cold`.
5. **Дії:**
   - `hot` → нотифікація менеджеру (в n8n — Slack `#sales`) **і** запис у
     реєстр лідів (в n8n — Google Sheets `Leads`);
   - `cold` → лише запис у реєстр;
   - відповідь `200` — `{ ok: true, segment: "hot" | "cold" }`.

## Що з цим робити в домашці (Task 2)

Відтворити цю логіку **кодом** у `app/` (TypeScript рекомендовано):

- зовнішні сервіси замінюємо локальними адаптерами: нотифікація —
  `console.log`/лог-файл, реєстр — CSV або JSON-файл у `app/data/`;
- тригер спрощуємо: CLI-скрипт, що читає JSON-заявки (або HTTP-ендпойнт на
  `node:http` — на ваш вибір);
- бізнес-правила 2–5 — **точно як вище**, і на них мають бути тести
  (мінімум: валідація, нормалізація бюджету, hot/cold-сегментація).
